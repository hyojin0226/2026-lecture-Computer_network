# 4주차 관찰

## 과제 1 · 신뢰성 있는 전송
Selective Repeat(창 8, timeout 32 step)를 사용했다. 재전송을 끈 대조 실험에서 손실만 있을 때 8바이트 뒤 정지했고, 중복/재정렬만 있을 때는 완료되어 먼저 해결해야 할 실패는 손실이었다. 수신자는 순번별로 버퍼링하고 이미 받은 패킷도 다시 ACK하되 출력에는 한 번만 넣는다.
2,000바이트의 최소 DATA 전송은 250회인데 seed 246/999에서 310/311회(1.240/1.244배), 994/926 step에 동일한 바이트로 복원됐다. seed 246의 ACK 전송 288회까지 합치면 598회로 DATA+ACK 최소 500회의 1.196배이며, 이는 채널 send 호출 기준이다.
원본 검증 외에 서로 다른 바이트 내용·빈 입력·부분 마지막 조각을 포함한 140개 검사(손실 20%, 중복 30%, 재정렬 80%)도 통과했다. ACK 중복은 이미 확인된 번호를 다시 진행시키지 않도록 처리했다.

## 과제 2 · 실제 연결 측정
직접 캡처한 SYN/SYN-ACK/ACK는 1/2/3번, 클라이언트/서버 ISN은 4100498673/1248996640이다. SYN의 MSS는 1460 B, WS shift 8(×256), SACK 허용이며 서버는 MSS 1250 B, shift 13(×8192), SACK 허용이다. ISN은 오래된 세그먼트 혼동과 번호 예측을 줄이기 위해 항상 0으로 고정하지 않는다.
SYN 자체는 스케일하지 않으며 ACK #3의 수신창은 255×256=65,280 B, #334는 2047×256=524,032 B인데 #366의 관측 최대 bytes-in-flight는 40,000 B였다. 수신창 고갈 증거는 없지만 수신자 캡처로 서버 cwnd나 단일 병목을 확정할 수 없고, RTT/ACK에 따른 cwnd 성장과 TLS·첫 응답 대기도 전체 처리량에 영향을 준다.
학교/집 Wi-Fi 각 5회의 처리량 중앙값은 63.98/46.26 Mbps, 범위는 46.88~86.83/45.82~48.87 Mbps(spread 62.4/6.6%), 핸드셰이크 중앙값은 10.73/9.25 ms였다. RTT가 길면 ACK 기반 slow start·혼잡회피의 cwnd 증가가 늦지만 집의 RTT가 더 짧아도 처리량은 낮으므로 이번 차이를 RTT만으로 설명할 수 없다. 무선 경합·대기열·DNS·서버 응답 변동도 후보이며, 상세 근거는 [task2_analysis.md](task2_analysis.md)에 기록했다.

## 과제 3 · 혼잡 제어 개선
창 64를 고정한 기준 구현은 goodput 986.75로 높지만 손실 37.4%, 재전송 2340회, 평균 큐 8.8로 전송 자원과 공유 링크의 지연을 낭비한다. slow start 뒤 ACK당 0.5/cwnd만큼 증가하고 손실 때 창을 65%로 줄이며 한 비행 분량의 ACK 동안 중복 감속을 억제했다.
개선 결과 goodput 972.75(기준의 98.58%), 손실 0.153%, 재전송 6회, 평균 큐 4.641로 strong이다. 창은 한 상수로 고정되지 않고 초기 구간 이후 약 20.14~31.00 사이를 반복하며, 링크의 BDP 약 20패킷을 유지하면서 일시적으로 큐 여유를 사용한다.
감속 뒤 유지 비율을 0.50→0.65로 완화하면 goodput 936.75→972.75로 늘지만 평균 큐 3.8295→4.641, 재전송 5→6으로 증가한다. 0.70에서는 goodput 증가 없이 큐 5.27125로 제한을 넘으므로 0.65를 선택했다(세부값: backoff_comparison.json). 이는 제공된 단일 흐름 시뮬레이션에 대한 결과다.
