과제 1: 동률 경로는 이웃을 이름순으로 탐색하고 힙에서 먼저 확정된 경로를 택했다(실제 OSPF 라우터는 동등 비용 경로를 ECMP로 함께 설치할 수도 있다).
u에서 w의 다음 홉은 x다(u-x-y-w 비용 3 < 직접 u-w 비용 5). u-x 단절 뒤 v는 v로 유지되고, w는 w로, x·y·z는 v로 다음 홉이 바뀐다.

과제 2: 2026-10-26 측정자 본인 노트북의 Docker Desktop 4.96.3·FRR 9.1.0으로 측정했다(Hello 10초, Dead 40초). 직접 연결되지 않은 서브넷을 r1은 172.20.0.0/16, r2는 172.19.0.0/16, r3는 172.18.0.0/16으로 학습했다; r1의 172.20 경로는 r2·r3 ECMP였다가 단절 후 r3 경유로 바뀌었다.
r1-r2 단절 재수렴은 4초, 복구는 11초, r1 eth0 비용 10→100 변경은 3초였다. 인터페이스 down은 즉시 감지되어 Dead 40초를 기다리지 않았고, 복구는 Hello·인접 형성이 필요했다; 비용 변경은 LSA/SPF로 반영됐으며 3초와 4초 차이는 1초 측정 해상도 안이다.
집에서 측정해 캠퍼스 이탈 지점은 특정할 수 없다(국내 경로의 hop 1은 192.168.0.1, hop 2는 무응답). Stanford는 CDN/AWS Global Accelerator를 거쳐 16홉에서 끝났고 해저 구간의 100ms 지연 상승은 관측되지 않아 케이블을 특정하지 못했다; 1.1.1.1은 9홉으로 근거리 anycast 경로를 시사하지만 위치를 확정하진 못하며, `*`는 ICMP 응답 필터링 또는 probe/응답 손실·제한으로 설명된다.

과제 3: 최단거리와 선택 트리의 부모를 O(V) 메모리로 유지하고, 선택 트리 링크 단절·악화 또는 더 짧은 새 경로가 생길 때만 전체 SPF를 실행했다. 1,000개 이벤트에서 오답 0, SPF는 1,001회에서 346회로 65% 줄었다.
벽시계는 기준 1.73초, 개선판 2.09초로 Python 상태 확인 비용 때문에 더 느렸지만, CPU와 SPF 재계산이 병목인 라우터에서는 반복 계산을 줄이는 것이 유리하다.
